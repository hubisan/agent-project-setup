# Adopt project setup

1. Inspect the actual target repo, `AGENTS.md`, existing agent/skill files, task conventions, and source document format. Keep its current structure.
2. Determine current need: wiki, project, or both. Distinguish the target's workflow from any optional coding workflow.
3. Summarize a **minimal adoption plan**: file ownership, canonical context, format default, tasks source, privacy scope, and any collisions. Reuse already stated preferences; ask only blocking decisions.
4. Preview exact changes and request approval before writing. An explicit user instruction to perform adoption counts as approval for the reviewed scope.
5. Add only owned instructions/pointers; preserve foreign `AGENTS.md` sections and installed skills. Never silently install a second conflicting copy.
6. Verify links, repeated-adoption behavior and actual saved files. State whether anything was committed or pushed.

**Done:** A new agent can read the target's project context and find the phase guide without requiring prior conversations. Leave uncertainties explicit.
