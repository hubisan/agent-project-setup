# Question presentation

Use one shared presentation convention for APS questioning workflows (including a future aps-brainstorm), without requiring another skill invocation.

- Pick the lightest interface that serves the question: conversation for simple/open questions, one-at-a-time choices for consequential independent decisions, grouped controls for closely related questions when the host supports them.
- Keep questions short, numbered within the session, and labelled with meaningful titles. Explain why the answer matters to the immediate goal.
- Provide distinct A/B/C alternatives only when they are genuinely useful; always permit an Other / own solution response and qualified choices.
- Mark the recommended answer explicitly, explain why and the most important trade-off. A visual preselection never counts as approval.
- Give users a way to add general remarks for a multi-question round. Preserve nuances, rather than forcing a multiple-choice code.
- Show progress/navigation only when the number of questions is actually known; never invent a fixed total to prolong an interview.
- Respect natural-language preferences such as “ask one at a time”, “make it quick”, and “show several together”.
- Interactive forms are optional; do not presume a specific UI library or provider. Plain Markdown/text must carry the same information and choices.
- After every response, update the unresolved question frontier and omit already settled, verifiable, reversible-default, redundant or deferred questions.
- Stop asking as soon as the user has provided enough to safely make useful progress.
