# Manual acceptance exercise: meal planner

The pilot must not modify the actual meal planner repository before a separately approved adoption.

1. **Discovery**: Given existing recipe/planning notes, `discover-project` describes the intended outcome and gives one useful next investigation without assuming an app.
2. **Shaping**: `shape-project` contrasts AI plus structured recipes, an existing tool and custom development. A non-app choice passes.
3. **Natural Planning**: `plan-project` selects next actions and distinguishes hypotheses from commitments.
4. **Handoff**: `handoff-project` includes decisions, sources, alternatives and next steps without fabricating results.
5. **Adoption**: `adopt-project-setup` reports collisions before writing, respects existing `AGENTS.md`, and adds no GTD/task tracker by default.
6. **Review**: `review-project` surfaces only relevant next actions and waiting follow-ups.

These are **planned**, not yet executed end-to-end tests.
